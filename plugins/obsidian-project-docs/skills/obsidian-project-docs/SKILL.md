# Obsidian Project Docs

Turn a software project's documentation into a single, well-organized, link-rich
Obsidian vault that Claude Code, Claude Desktop, and the human all share through
git. This encodes a full methodology that was proven end-to-end on a real
project, including the setup gotchas that cost real time.

## Mental model (read this first)

There are **three participants** that all operate on the **same on-disk `/docs`
folder**, kept in sync by **git**:

- **Claude Code** (terminal) — works directly on the repo files on disk. Best
  for bulk file surgery: consolidating, moving, categorizing, migrating,
  editing `.gitignore`, git commits. Git-native, works even when Obsidian is
  closed.
- **Claude Desktop** — connects to the vault through the **Obsidian "Claude
  Code MCP" plugin** (an MCP server that runs *inside* Obsidian). Vault-aware
  (understands notes/links/tags), reflects changes live in the open app. Best
  for day-to-day read/update of notes. **Requires Obsidian to be running.**
- **Obsidian** — the human's editing surface, and the host of the MCP server.

The vault lives at **`<repo>/docs`** — not the repo root (that would index
`node_modules` and code). One repo holds both code and docs, so a single
`git pull` syncs everything to the same point in time.

## When each track applies

This skill has **two tracks**. Figure out which the user needs (often both, in
order):

1. **Track A — Claude Code side** (`references/claude-code-setup.md`):
   consolidate + categorize + migrate existing docs into the vault, add
   frontmatter and wikilinks. Run this in a normal interactive session, **not**
   inside an autonomous loop (loopcraft/ralph), because it's judgment-heavy and
   needs human approval gates.

2. **Track B — Claude Desktop side** (`references/desktop-mcp-setup.md`):
   install/configure the Obsidian MCP plugin, wire Claude Desktop to it, and
   generate + apply project instructions so the vault becomes the source of
   truth.

## Track A — Consolidate & migrate (Claude Code)

Full procedure in `references/claude-code-setup.md`. The essence:

1. **Inventory first, move nothing yet.** Find every doc across the repo,
   including files generated by tools (superpowers, omc, loopcraft, `.claude/`).
   Classify each: `[KEEP-tool]` machinery, `[KEEP-log]` session scratch,
   `[MOVE-knowledge]` real project knowledge, `[MIXED]` machinery containing
   knowledge. Produce a table and **stop for human approval.**
2. **Never delete.** Move files, leaving a short **stub** at the old path
   (frontmatter `status: stub`, `moved_to: ...`, plus a wikilink) so nothing
   breaks.
3. **Folder skeleton as a hypothesis, not a mandate.** Start from the default
   skeleton in `assets/vault-structure.md`; propose additions/merges only where
   the actual docs don't fit. Keep top-level folders to ~6–8; avoid one-folder-
   per-file over-splitting.
4. **Add frontmatter + wikilinks.** Every note gets `title`, `status`,
   `source`, `updated`. Link related notes with `[[...]]` to prevent
   re-fragmentation.
5. **Reconstruct ADRs** for past decisions where the rationale is recoverable;
   use `assets/adr-template.md`. If a rationale is uncertain, leave a
   "confirm needed" placeholder — never invent one.
6. **Update `.gitignore`** (only the churn-y Obsidian files) and **update
   `CLAUDE.md`** to declare the vault the source of truth so fragmentation
   doesn't recur.

A ready-to-paste, generalized version of the whole Track-A prompt is in
`assets/migration-prompt.md` — hand it to Claude Code and fill the blanks.

## Track B — Connect Desktop & apply instructions

Full procedure + the setup gotchas in `references/desktop-mcp-setup.md`. The
essence:

1. **Open `<repo>/docs` as its own vault** in Obsidian (separate from any
   personal mega-vault, so the MCP only sees this project).
2. **Install the "Claude Code MCP" community plugin** in that vault. It exposes
   two servers: a **WebSocket** server (for Claude Code via `/ide`) and an
   **HTTP/SSE** server (for Claude Desktop).
3. **If you run more than one vault, give each a unique HTTP port** (e.g. this
   project 22361, another 22360) or you'll get a port conflict when both are
   open.
4. **Wire Claude Desktop** to the SSE endpoint using the **`mcp-remote` stdio
   bridge** — do NOT paste a bare `"url"` into `claude_desktop_config.json`
   (Desktop's config validates stdio only and will silently drop it). Config
   snippet in `assets/claude-desktop-config-snippet.md`. Watch the nvm/PATH
   gotcha in troubleshooting.
5. **Connect Claude Code** (if used on this machine): run `claude` → `/ide` →
   select "Obsidian". No config file needed.
6. **Verify** by listing vault files and doing one write test.
7. **Generate project instructions** from `assets/project-instructions-template.md`,
   tailored to this project's MCP server name and folder categories, and paste
   into the claude.ai project's Custom Instructions.

## Guardrails (non-negotiable)

- **Never delete docs** — move + stub, or archive. Keep a migration map.
- **Never touch tool machinery** (superpowers/, plans/, specs/, `.claude/`)
  except to *update* `CLAUDE.md` with the source-of-truth rule.
- **Inventory before migrating**; get human sign-off on the classification.
- **Don't run Track A inside an autonomous loop** — it needs approval gates.
- **Never invent facts** written into the vault; mark unconfirmed values with a
  placeholder tag.
